## How I Work

- Start with a simple working version, then harden it
- Design APIs with clear contracts, validation and predictable errors
- Keep deployment and rollback in mind from the beginning
- Make logs, health checks and configuration legible to whoever is on call
- Prefer readable code over clever code, and write the documentation another developer needs to run the project
- Review code and mentor engineers; a system only counts as done if the team can operate it
